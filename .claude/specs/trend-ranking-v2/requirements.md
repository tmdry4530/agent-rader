# 트렌드 수집·랭킹 개편 v2 (trend-ranking-v2) — 요구사항

## 1. Overview

### 문제 정의
trend-discovery(v1) 배포 후 실사용에서 드러난 한계:

1. **커버리지 구멍** — 실제로 1주일에 2만 스타를 받은 레포가 대시보드에 아예 안 뜬다. base 슬라이스는 스타 절대 상위 30개만 가져오는데(`ETL_PER_QUERY=30`), 인기 니치엔 50k~100k 거대 레포가 널려서 2만짜리가 top 30에 못 들면 **표본에 진입조차 못 한다.** 표본에 없으면 스냅샷·델타·노출이 전부 불가능.
2. **신생 급상승이 "예전 큰 레포 숫자만 갱신"되는 느낌** — 창이 90일로 넓어 3개월 된 레포가 눌러앉고, 절대 증가량(star_delta) 순이라 이미 큰 신생이 상위를 독점한다. "며칠 전 생겼는데 폭발 중"인 진짜 신생이 묻힌다.
3. **정체 레포가 목록을 채운다** — Top Movers·신생 급상승 모두 최소 기준 없이 `LIMIT N`이라, 니치가 조용하면 증가 0에 가까운 레포까지 자리를 차지한다.
4. **관심 레포가 안 보인다** — 북마크 기능은 있으나 대시보드에 노출되지 않아 사용자가 찜한 레포를 한눈에 볼 수 없다.

### 목표
- 수집 깊이를 100으로 넓혀 "오래됐지만 지금 폭발 중"인 레포가 표본에 들어오고, Top Movers(성장률 상위)에서 보이게 한다.
- 신생 급상승을 "진짜 최신(30일 이내) + 빠른 증가" 속도 점수로 재정의해 어린 폭발 레포가 상위에 오게 한다.
- 최근 증가가 없는 정체 레포는 목록에서 감춘다.
- 관심 레포(북마크) 섹션을 대시보드에 추가한다.

### Non-goals
- GitHub Trending 페이지 스크래핑 — 공식 Search API만 사용(증가순 정렬 부재는 표본 확대로 우회)
- Top Movers 정렬을 절대 증가순으로 변경 — 이번엔 성장률(%) 유지 (커버리지만 확보하면 노출됨)
- 스냅샷 보존 정책·다운샘플 — 별도 기능
- 100위 밖 레포 포착(초거대 니치) — 깊이 100의 한계를 감수

### 성공 기준
- 특정 검색어에서 스타 절대 상위 30~100위 사이인 급상승 레포가 수집·추적되어 Top Movers에 노출된다.
- 신생 급상승 목록이 "30일 이내 생성 + 최근 증가 있는" 레포만, 속도(증가÷나이) 순으로 표시된다.
- 최근 증가가 0인 레포는 어느 목록에도 나타나지 않으며, 대상이 없으면 빈 상태 안내가 뜬다.
- 대시보드에 관심 레포 섹션이 있고 본인 북마크만 표시된다.

## 2. 요구사항

### R1. 수집 커버리지 확대

**유저스토리:** 사용자로서, 지금 폭발 중인 레포를 놓치지 않기 위해, 스타 상위 일부만이 아니라 더 넓은 표본이 수집되기를 원한다.

**인수 조건:**
- R1.1 WHEN 각 슬라이스를 수집하면, THE SYSTEM SHALL 검색어당 스타 상위 `ETL_PER_QUERY`(기본 **100**)개까지 가져온다
- R1.2 WHERE GitHub Search의 `per_page` 상한이 100이므로, THE SYSTEM SHALL 100 이하는 단일 요청으로 처리한다(추가 API 비용 없음)
- R1.3 IF `ETL_PER_QUERY`가 100을 초과하도록 설정되면, THEN THE SYSTEM SHALL 최대 100으로 제한한다(단일 페이지 상한)

### R2. 신생 급상승 재정의 (리얼 핫 속도 점수)

**유저스토리:** 사용자로서, 방금 생겼는데 빠르게 크는 진짜 핫한 레포를 발견하기 위해, 최신성과 최근 증가를 함께 반영한 순위를 원한다.

**인수 조건:**
- R2.1 WHEN 신생 급상승을 조회하면, THE SYSTEM SHALL 생성 후 `RISING_WINDOW_DAYS`(기본 **30**)일 이내인 레포만 대상으로 한다
- R2.2 WHEN 순위를 매기면, THE SYSTEM SHALL 속도 점수 `star_delta / max(생성 후 경과일, 1)` 내림차순으로 정렬한다 (어릴수록·최근 많이 오를수록 상위)
- R2.3 IF 레포의 `star_delta`가 0 이하이면, THEN THE SYSTEM SHALL 신생 급상승에서 제외한다 (정체 레포 숨김)
- R2.4 WHILE 수집 대상 표본은, THE SYSTEM SHALL 기존 트렌드 슬라이스(`created:>ETL_TREND_WINDOW_DAYS`, 기본 90) 그대로 유지한다 (수집은 넓게, 노출은 30일로 좁게 — 30~90일 레포도 추적되어 Top Movers엔 나올 수 있음)

### R3. 정체 레포 숨김

**유저스토리:** 사용자로서, 안 움직이는 레포에 목록이 낭비되지 않도록, 최근 증가가 없는 레포는 감춰지기를 원한다.

**인수 조건:**
- R3.1 WHEN Top Movers(성장률 상위)를 조회하면, THE SYSTEM SHALL `star_delta > 0`인 레포만 포함한다
- R3.2 WHEN 신생 급상승을 조회하면, THE SYSTEM SHALL `star_delta > 0`인 레포만 포함한다 (R2.3과 동일)
- R3.3 IF 조건을 만족하는 레포가 하나도 없으면, THEN THE SYSTEM SHALL 해당 패널에 빈 상태 안내를 표시한다(에러 아님)

### R4. 관심 레포(북마크) 대시보드 노출

**유저스토리:** 사용자로서, 내가 추적하려고 찜한 레포를 한눈에 보기 위해, 대시보드에서 북마크 목록을 원한다.

**인수 조건:**
- R4.1 WHEN 대시보드를 열면, THE SYSTEM SHALL 요청 사용자의 `is_bookmarked = true` 레포를 별도 섹션에 표시한다
- R4.2 WHEN 관심 레포를 표시하면, THE SYSTEM SHALL 레포명·언어·스타·최근 증가(star_delta)를 함께 보여준다
- R4.3 WHERE 이 목록은, THE SYSTEM SHALL 요청 사용자 데이터만(`user_id` 스코프) 조회한다
- R4.4 IF 북마크한 레포가 없으면, THEN THE SYSTEM SHALL 빈 상태 안내("관심 레포를 북마크해 보세요")를 표시한다

### R5. 설정

**유저스토리:** 운영자로서, 커버리지·신생 창을 조정하기 위해, 환경변수로 바꾸고 싶다.

**인수 조건:**
- R5.1 WHEN `ETL_PER_QUERY`(기본 100)를 설정하면, THE SYSTEM SHALL 수집 깊이에 적용한다(최대 100)
- R5.2 WHEN `RISING_WINDOW_DAYS`(기본 30)를 설정하면, THE SYSTEM SHALL 신생 급상승 노출 창에 적용한다
- R5.3 IF 환경변수가 없거나 비정상 값이면, THEN THE SYSTEM SHALL 기본값(100 / 30)을 사용한다
