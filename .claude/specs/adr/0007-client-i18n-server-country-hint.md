# ADR-0007: 클라이언트 번역 리소스 + 서버 국가 힌트

- **날짜**: 2026-08-10
- **상태**: 승인됨
- **관련 기능**: plain-language-copy

## 맥락

쉬운 제품 문구를 한국어와 영어로 제공하고, 첫 방문자의 국가에 맞춰 언어를 자동 선택해야 한다. 현재 앱은 React SPA와 Express API를 같은 Railway 서비스에서 제공하며 다국어 기반이 없다. Railway의 접속 거점 헤더는 실제 사용자 국가를 뜻하지 않고, 브라우저의 정확한 위치 API는 권한 요청과 과도한 정밀도를 동반한다.

번역 책임을 어디에 둘지, 국가를 어떤 방식으로 판정할지, 외부 장애와 위치 정보 노출을 어떻게 제한할지 결정해야 한다.

## 검토한 대안

### 번역 관리

1. **`i18next` + `react-i18next` 클라이언트 리소스** — 장점: React 반응형 언어 변경, 보간·복수형, 확장성과 검증 생태계. 단점: 런타임 의존성 2개 추가.
2. **직접 만든 React Context + 문자열 객체** — 장점: 의존성 없음. 단점: 보간·복수형·누락 검사·비React 오류 경계까지 직접 유지해야 한다.
3. **백엔드에서 모든 메시지 번역** — 장점: 서버 오류가 이미 번역됨. 단점: SPA 화면 문자열과 서버 문자열이 분산되고 사용자가 즉시 언어를 바꾸기 어렵다.

### 국가 판정

1. **MaxMind GeoLite Country 웹 서비스** — 장점: 국가 단위만 조회, 로컬 DB 갱신 운영 없음, 공식 Node 클라이언트. 단점: 방문자 IP가 MaxMind로 전송되고 계정 키·네트워크 의존성이 생김.
2. **GeoLite Country 로컬 DB** — 장점: IP가 서비스 밖으로 나가지 않음. 단점: 라이선스 키 기반 다운로드와 주기적 갱신, Docker 이미지·시작 절차 관리가 추가됨.
3. **Railway `X-Railway-Edge`** — 장점: 추가 서비스 없음. 단점: 가장 가까운 접속 거점일 뿐 실제 사용자 위치가 아니어서 요구사항을 충족하지 못함.
4. **`Accept-Language`만 사용** — 장점: 개인정보와 외부 의존성 없음. 단점: 국가 기반 선택 요구를 충족하지 못함.
5. **브라우저 Geolocation API** — 장점: 위치 정밀도 높음. 단점: 권한 팝업, 도시·좌표 수준의 불필요한 개인정보, 거부 시 UX 저하.

## 결정

- 번역은 `i18next`와 `react-i18next`를 사용해 프론트엔드 리소스에서 관리한다. API의 안정적인 오류 코드는 번역 키로 매핑하고 서버 메시지 원문은 사용자 화면에 직접 노출하지 않는다.
- 국가 판정은 Express 서버가 Railway의 검증된 `X-Real-IP`를 MaxMind GeoLite Country 웹 서비스에 전달해 ISO 국가 코드만 얻는다.
- 외부 조회는 800ms 안에 끝내고 모든 실패를 `Accept-Language`, 이후 영어 기본값으로 대체한다.
- 원본 IP·국가·판정 결과를 DB나 로그에 저장하지 않는다. 반복 요청 완화용 캐시는 프로세스마다 무작위 키로 HMAC한 IP와 국가 코드만 최대 10분 보관한다.
- 사용자의 수동 선택은 브라우저 `localStorage`에 저장해 모든 자동 판정보다 우선한다.

## 결과

- 새 언어는 번역 리소스와 국가-언어 매핑을 추가하는 방식으로 확장할 수 있다.
- 첫 접속은 GeoLite 응답 시간만큼 최대 800ms 늦어질 수 있지만 문구 깜빡임은 없다. 장애 시 서비스는 계속 열린다.
- MaxMind 계정·키와 런타임 의존성 1개가 백엔드 운영에 추가된다. 외부 공급자의 IP 처리 사실을 개인정보 안내에 밝혀야 한다.
- GeoLite 장애나 정책 변경이 반복되면 `CountryResolver` 구현만 로컬 DB 방식으로 교체할 수 있다. 공개 API와 프론트엔드는 영향을 받지 않는다.
