# 쉬운 제품 문구·다국어 개편 (plain-language-copy) — 요구사항

## 1. Overview

### 문제 정의

현재 화면에는 `ETL`, `Queries`, `Repos`, `snapshot`, `Δ`, `mock`처럼 구현을 아는 사람에게만 익숙한 표현이 섞여 있다. 개발에 관심은 있지만 전문 용어에 익숙하지 않은 사용자는 버튼을 눌렀을 때 무엇이 일어나는지, 표의 숫자가 무엇을 뜻하는지 바로 이해하기 어렵다.

### 목표

- 제품 사용에 필요한 문구를 행동과 결과 중심의 쉬운 표현으로 바꾼다.
- 같은 개념은 모든 화면·도움말·오류 메시지에서 같은 용어로 표현한다.
- GitHub 고유 개념은 유지하되 처음 보는 사용자도 문맥으로 뜻을 알 수 있게 한다.
- 방문자의 국가와 선호 언어를 참고해 지원하는 언어 중 가장 알맞은 언어로 화면을 자동 표시한다.
- 사용자가 자동 선택된 언어를 언제든 직접 바꾸고, 이후 방문에도 그 선택을 유지할 수 있게 한다.

### 기본 용어

| 기존 표현 | 한국어 화면 | 영어 화면 |
|---|---|---|
| ETL / ETL 실행 | 수집 / 수집 실행 | collection / run collection |
| Query / Queries | 수집 조건 | collection filter(s) |
| Repo / Repos / 레포 | 프로젝트 | project(s) |
| snapshot | 수집 기록 | collection record |
| delta / Δ | 증가량 | increase |
| keyword / topic | 키워드 / 주제 | keyword / topic |
| Lang / Stars | 언어 / 스타 | language / stars |
| Actions | 작업 | actions |
| KST | 한국 시간 | Korea time |
| mock | 예시 데이터 | sample data |

### 언어 선택 우선순위

1. 사용자가 직접 선택해 저장한 언어
2. 국가 단위 위치에 알맞고 브라우저 선호 언어에도 포함된 지원 언어
3. 국가별 기본 언어
4. 브라우저가 선호하는 지원 언어
5. 기본 언어인 영어

초기 지원 언어는 한국어(`ko`)와 영어(`en`)로 가정한다. 이후 언어를 추가할 때는 같은 선택 규칙과 번역 구조를 확장한다.

### Non-goals

- 코드 식별자, 타입명, API 경로, DB 컬럼명 변경
- README와 개발자용 로그·주석의 기술 용어 전면 개편
- 화면 구조·스타일·기능 동작 변경
- GitHub, 스타, 이슈, 토픽 같은 서비스 고유 개념 제거
- GPS·브라우저 위치 권한을 이용한 도시 단위 위치 확인
- IP 주소, 국가 정보 또는 위치 판정 결과의 영구 저장·사용자 추적
- GitHub 프로젝트 이름·설명·사용자 입력처럼 서비스가 작성하지 않은 콘텐츠의 자동 번역

## 2. 요구사항

### R1. 탐색과 페이지 이름

- R1.1 WHEN 사용자가 상단 메뉴를 보면, THE SYSTEM SHALL `Dashboard`, `Queries`, `Repos` 대신 `대시보드`, `수집 조건`, `프로젝트`를 표시한다.
- R1.2 WHEN 각 페이지와 통계 카드를 표시하면, THE SYSTEM SHALL 선택한 언어에서 기술 용어보다 이해 가능한 제목을 우선한다.
- R1.3 WHEN 예시 데이터 모드를 표시하면, THE SYSTEM SHALL `mock` 또는 `목 데이터` 대신 `예시 데이터`라고 표시한다.

### R2. 수집 흐름

- R2.1 WHEN 사용자가 수집 버튼·도움말·완료 메시지를 보면, THE SYSTEM SHALL `ETL`을 노출하지 않고 `수집`으로 표현한다.
- R2.2 WHEN 수집이 완료되면, THE SYSTEM SHALL `repos`, `snapshots` 대신 `프로젝트`, `수집 기록` 단위로 결과를 알려준다.
- R2.3 WHEN 수동 수집 한도를 안내하면, THE SYSTEM SHALL `KST 자정` 대신 `자정(한국 시간)`이라고 표시한다.
- R2.4 WHEN 수집 조건의 종류를 선택하면, THE SYSTEM SHALL `keyword`, `topic` 대신 `키워드`, `주제`를 표시하고 각 검색 범위를 쉬운 문장으로 설명한다.

### R3. 프로젝트와 지표

- R3.1 WHEN 목록·상세·빈 상태·삭제 확인에서 저장소를 지칭하면, THE SYSTEM SHALL `repo/레포` 대신 `프로젝트`를 사용한다.
- R3.2 WHEN 표 머리글을 표시하면, THE SYSTEM SHALL `Repo`, `Lang`, `Stars`, `Δ`, `Age`를 각각 `프로젝트`, `언어`, `스타`, `증가량`, `만들어진 지`처럼 뜻이 드러나는 표현으로 표시한다.
- R3.3 WHEN 상세 화면에서 `query`, `snapshot`, `issues` 정보를 보여주면, THE SYSTEM SHALL `수집 조건`, `수집 기록`, `열린 이슈`로 표현한다.
- R3.4 WHEN 24시간 증가량을 표시하면, THE SYSTEM SHALL `Δ24H` 대신 `최근 24시간 증가`처럼 비교 기간과 의미가 함께 드러나게 한다.

### R4. 첫 사용 안내

- R4.1 WHEN 비로그인 사용자가 소개 화면을 읽으면, THE SYSTEM SHALL `니치`, `매칭`, `스냅샷`, `시계열`, `생태계` 대신 `관심 분야`, `맞는`, `수집 기록`, `시간에 따른 변화`, `관련 기술 분포`를 사용한다.
- R4.2 WHEN 사용 순서를 안내하면, THE SYSTEM SHALL `키워드 등록 → 자동 수집 → 급상승 확인`의 행동과 결과를 일반 문장으로 설명한다.
- R4.3 WHEN 예시 화면을 보여주면, THE SYSTEM SHALL 실제 로그인 후 화면과 동일한 언어와 용어를 사용한다.

### R5. 오류와 상태 메시지

- R5.1 IF 사용자 입력이 잘못되면, THEN THE SYSTEM SHALL `query_id`, `query_type` 같은 내부 필드명 대신 `선택한 수집 조건`, `검색 방식`을 사용한다.
- R5.2 IF GitHub 인증 또는 내부 요청이 실패하면, THEN THE SYSTEM SHALL `401`, `base/trend`, 내부 ID, 환경변수명 같은 구현 세부사항을 노출하지 않는다.
- R5.3 IF 예상하지 못한 오류가 발생하면, THEN THE SYSTEM SHALL 사용자가 다음 행동을 알 수 있는 현재 선택 언어의 메시지를 표시한다.
- R5.4 WHEN 백엔드와 예시 데이터 모드가 같은 상황을 처리하면, THE SYSTEM SHALL 같은 사용자 문구를 반환한다.
- R5.5 WHEN 표시 언어가 변경되면, THE SYSTEM SHALL 오류·확인·완료·빈 상태 메시지도 선택한 언어로 표시한다.

### R6. 일관성과 검증

- R6.1 THE SYSTEM SHALL 문구 변경 후에도 기존 버튼의 접근 가능한 이름과 의미를 유지하거나 더 명확하게 한다.
- R6.2 THE SYSTEM SHALL 번역된 문구가 데스크톱·태블릿·모바일 레이아웃을 깨뜨리지 않게 한다.
- R6.3 THE SYSTEM SHALL 한국어 사용자 화면에서 `ETL`, `Repos`, `Queries`, `snapshot`, `query_id`, `query_type`, `Δ24H`, `mock`이 남아 있지 않게 한다. 영어 화면에서도 같은 개념을 위 기본 용어의 쉬운 표현으로 표시한다. 단, 개발자 전용 코드·로그·주석은 제외한다.

### R7. 위치 기반 자동 언어 선택

- R7.1 WHEN 사용자가 저장된 언어 선택 없이 처음 접속하면, THE SYSTEM SHALL 접속 IP로부터 국가 단위 위치만 확인해 지원 언어를 선택한다.
- R7.2 WHEN 한 국가에서 여러 언어를 사용할 수 있으면, THE SYSTEM SHALL 브라우저 선호 언어를 함께 비교해 지원 언어를 선택한다.
- R7.3 IF 국가 정보를 확인할 수 없거나 위치 조회가 실패하면, THEN THE SYSTEM SHALL 서비스 접속을 막지 않고 브라우저 선호 언어를 사용한다.
- R7.4 IF 국가와 브라우저 선호 언어 모두 지원 언어와 맞지 않으면, THEN THE SYSTEM SHALL 영어를 표시한다.
- R7.5 THE SYSTEM SHALL 언어 자동 선택을 위해 기기의 정확한 위치 권한을 요청하지 않는다.
- R7.6 THE SYSTEM SHALL 위치 판정에 사용한 IP 주소·국가·판정 결과를 애플리케이션 DB에 저장하지 않는다.

### R8. 언어 직접 선택과 다국어 품질

- R8.1 WHEN 사용자가 로그인 전후의 공통 화면을 보면, THE SYSTEM SHALL 접근 가능한 언어 선택 메뉴를 제공한다.
- R8.2 WHEN 사용자가 언어를 직접 선택하면, THE SYSTEM SHALL 자동 판정 결과보다 우선하고 이후 방문에도 선택을 유지한다.
- R8.3 WHEN 표시 언어가 정해지면, THE SYSTEM SHALL 문서의 `lang` 속성과 날짜·숫자 표기에도 같은 언어 규칙을 적용한다.
- R8.4 THE SYSTEM SHALL 화면 문구를 번역 키로 관리해 한국어와 영어가 한 화면에 의도치 않게 섞이지 않게 한다.
- R8.5 THE SYSTEM SHALL 새 지원 언어를 추가할 때 위치 판정 로직을 다시 작성하지 않고 국가-언어 매핑과 번역 리소스를 확장할 수 있게 한다.

## 3. 프로젝트 제약과 검증

- 명령: 백엔드 `npm test`, 프론트엔드 `npm run typecheck`와 `npm run build`.
- 브라우저: 로그인 화면과 예시 데이터 모드의 대시보드·수집 조건·프로젝트·상세 화면을 320px와 데스크톱에서 확인한다.
- 언어: 한국·비한국 국가, 위치 조회 실패, 브라우저 언어, 저장된 수동 선택의 우선순위를 각각 검증한다.
- 번역: 한국어·영어에서 모든 주요 흐름과 오류 상태를 확인하고, 누락된 번역 키가 없음을 자동 검사한다.
- 항상: 기존 기능·API 계약·에러 코드를 유지하고 사용자에게 표시되는 메시지만 바꾼다.
- 먼저 승인: 새 용어 도입, 기능 의미 변경, API 응답 구조 변경, 위치 조회용 외부 서비스·패키지 추가.
- 금지: 코드 식별자 일괄 이름 변경, 관련 없는 UI 재설계, 사용자 소유 미추적 파일 수정, 정확한 위치 권한 요청, 위치 정보 저장.

## 4. 확정된 결정

- 첫 배포는 한국어와 영어만 지원하고, 다른 언어는 번역 리소스를 추가하는 후속 작업으로 둔다.
- 국가 확인 구현은 Railway의 접속 거점 헤더를 사용하지 않는다. 실제 국가 단위 판정이 가능한 IP 국가 조회 방식은 설계 단계에서 비교하고, 외부 서비스나 패키지 추가 전에 승인받는다.
- 위 기본 용어, 언어 선택 우선순위, 위치 정보 비저장 원칙을 적용한다.
